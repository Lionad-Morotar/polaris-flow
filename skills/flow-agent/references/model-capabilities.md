# flow-agent 模型能力偏好

本文件描述各模型的能力特点，供主代理和子代理参考，**不直接影响 `flow-agent` 的模型选择逻辑**。模型选择由 `references/model-mapping.md` 中的 `--effort` 规则决定。

## kimi-k3

- 顶尖能力：和 glm-5.3 一致的顶尖编码能力，以及带多模态；
- 适用场景：复杂任务、需要多模态输入时、擅长编程、游戏 3D 和知识任务；

## kimi-k3-full

- 与 `kimi-k3` 同一模型，强度等同，区别仅在上下文档位：`kimi-k3` 为 256k（消耗更低，日常默认），`kimi-k3-full` 为 1M 全量；
- 适用场景：`--deep` 深入审查、审查对象上下文极长或需要全量上下文推理时；light 审查无需使用此档位；

## qwen-3.8-max

- 综合能力：顶级性能（尤其是通用知识如芯片、生物等和编程正交领域），推理深度好，速度快，性价比非常低；
- 适用场景：多模态、长时任务；

## glm-5.3

- 综合能力：顶尖编码和安全能力；
- 适用场景：复杂代码审查、架构与安全性审查、需要强推理时；

## glm-5.3-flash

- 定位：`glm-4.7`（`-flash`）的替代；综合能力略胜 `deepseek-v4-flash`，响应迅速；
- 适用场景：coding 与办公场景双修；审查编队中 GLM 族的低消耗档——light 模式 `--effort=ultra`/`fable` 的 GLM 视角、显式 `--target-model glm-5.3-flash` 的专项检查；

## deepseek-v4-flash

- 综合能力：顶尖性价比，响应迅速，不错的智能水平；
- 适用场景：主代理把需求与做法描述清楚后交给它执行的快速任务；审查编队中提供低延迟的补充视角；`--effort=max` 时作为第三视角，提供与主模型和反选模型不同的发现；主力模型；

## minimax-m3

- 状态：暂时禁用；
- 综合能力：一般；
- 适用场景：`--effort=ultra` 时启动，用于穷尽式多视角验证；
