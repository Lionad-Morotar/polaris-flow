# flow-agent Prompt 模板

本文件提供 `flow-agent` 的通用 prompt 框架与 light 审查指引。调用方通过 `--task` 描述自己用什么模型做了什么，`flow-agent` 据此注入上下文，从正交视角发起审查。

## 审查模式：light（默认）/ full

`flow-agent` 默认以 **light 模式**发起审查——快速正交 sanity check，不是穷尽审计。需要逐领域详查时显式传 `--deep`。调用方拟 prompt 时应遵循下面的 light 边界；脚本在 light 模式下还会自动注入 preamble 保底，确保即使调用方 prompt 偏重也带着轻量框定。

### light 审查边界（核心指引）

正交审查的增值在于"用不同模型视角捕捉主代理盲区"，而非替代主代理的完整验证。light 模式下：

**只报告会真正造成故障的发现**
- 逻辑错误、安全漏洞、数据损坏或丢失、权限越权、崩溃、资源泄漏

**跳过这些（不属于正交审查的增值范围）**
- 代码风格、命名、可读性等次要问题
- 主代理已用单测 / typecheck / lint 覆盖的验证点
- 没有具体失败场景支撑的纯理论性边界

**不要做**
- 逐行 review、穷举所有输入边界、主动搜索其他领域或文档

**时间预期是分钟级。** 没有值得主代理立即注意的高/中严重度发现时，整份输出只回一行"未发现高严重度问题"——这是有效结论，不是失职。禁止罗列已验证的角度/路径清单、复述验证过程或成功路径分析、附 Insight/总结/低严重度观察：验证叙述对调用方无信息量，纯消耗 token。

### light preamble（脚本默认注入）

`run-external-review.py` 在 light 模式下会自动把以下前言拼接到调用方 prompt 之前（`--deep` 与 `--no-preamble` 时不注入）。其他 agent 拟 prompt 时可参考这段措辞，让审查保持轻量：

`--no-preamble` 服务流程驱动审查：调用方 prompt 已完整定义审查流程与输出契约（如 flow-dev DevLoop 让外部模型按 flow-code-review 流程执行并输出 findings JSON），前言的「快速 sanity check / 一行结论」框定会与之冲突，故跳过注入；校验与模型选择仍按 light。

```text
【审查模式：light 正交审查】
这是一次快速正交 sanity check，不是穷尽审计。只报告会真正造成故障的高/中严重度发现（逻辑错误、安全漏洞、数据损坏或丢失、权限越权、崩溃、资源泄漏）。跳过风格/命名/可读性，跳过主代理已用单测或 typecheck 覆盖的验证，跳过无具体失败场景的纯理论边界。不要逐行 review、不要穷举输入边界、不要搜索其他领域。分钟级完成；没有关键发现就明确回复"未发现高严重度问题"。无高/中严重度发现时，整份输出仅这一行结论——禁止罗列已验证的角度/路径清单、复述验证过程或成功路径分析、附 Insight/总结/低严重度观察，验证叙述对调用方无信息量，纯消耗 token。需要深入审计请用 --deep 重新发起。
```

## 通用框架

```markdown
# 正交审查请求 — <slug>

## 上下文
- 任务：<task-description>
- 被审查内容路径：<target>
- 本次审查模型：<target-model>（flow-agent 会在调用各目标模型前自动替换为实际模型名，例如 `glm-5.3` 或 `deepseek-v4-flash`）

## 审查要求

正交审查的视角：主代理在下方**陈述其 code-review 已查的维度**（简单事实，不含结论）。
审查模型据此了解覆盖范围，自主检索 diff 与测试还原主代理真正做了什么，从覆盖之外或
验证方式本身的缺陷切入——不要顺着主代理列出的维度复查，那会复现主代理的盲区。

调用方填写原则：只列维度、陈述事实（"查了 X"），不下达"重点关注 X"的审查指令（那会把
审查模型拉回主代理视角），也不主动暴露自评盲区（那同样是用主代理视角引导方向）。

### 主代理 code-review 已查维度（调用方填写：只列维度，陈述事实）
- <维度 1>（<简述范围>）
- <维度 2>（<简述范围>）
- ...

输出纪律：每条发现含位置（如适用）、问题描述、风险等级、建议验证方式；不展开修复代码；
无关键发现时整份输出仅一行"未发现高严重度问题"——不罗列已验证角度、不复述验证过程/成功路径、
不附低严重度观察，不为凑数报告次要问题。

## 被审查内容摘要
<调用方在此处注入被审查内容的摘要或全文>
```

## 输出示例

```markdown
## 正交发现

### [严重度 高] 1. xxx
- **证据**：...
- **影响**：...
- **建议**：...

### [严重度 中] 2. xxx
...

## 总评
- 与前置审查的关系：...
- 是否建议继续：...
```

无高/中严重度发现时，完整输出仅一行：

```text
未发现高严重度问题
```

## 调用方示例

```bash
flow-agent docs/thoughts/2026-07-07-optimize-flow.md \
  --task "glm-5.3 完成 UltraThoughts 需求分析" \
  --slug optimize-flow-ultrathoughts \
  --caller-model glm-5.3 \
  --effort max \
  --target-model auto \
  --output-dir docs/reviews
```

`--effort max` 且 caller 为 `glm-5.3` 时，会生成：

```text
docs/reviews/2026-07-07-optimize-flow-ultrathoughts/
  ├── prompt.md
  ├── review-kimi-k3.md
  └── review-deepseek-v4-flash.md
```
