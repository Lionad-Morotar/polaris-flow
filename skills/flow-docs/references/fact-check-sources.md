# 搜索工具链与信源分层

由 SKILL.md Workflow B Step 2 调起。定义核查分支的搜索工具链与 fallback 顺序、搜索预算、T1–TX 信源分层与循环引用检测。

## 搜索工具优先级与 fallback

使用 `deepseek-search`（CLI，`--json` 供程序消费）/ `open-websearch`（MCP：`mcp__open-websearch__search` + `mcp__open-websearch__fetchWebContent`）/ `glm-*`（MCP）搜索与获取网页内容，出错时 fallback 到 `flow-web`。任何时候不使用内置 WebSearch/WebFetch。
工具链全部不可用：停止并报告，绝不凭先验知识编造证据。

- 1 — `deepseek-search`：CLI，带 `--json` 供程序消费
- 2 — `open-websearch`：MCP：`mcp__open-websearch__search` + `mcp__open-websearch__fetchWebContent`
- 3 — `glm-*`：MCP
- fallback — `flow-web`：浏览器自动化技能，前三者出错时启用

同一论断的不同类别查询并行执行；不同论断之间也可并行处理。

## 搜索预算

- quick：每论断搜索工具调用上限 1–2 次；超限处理 终止该论断，返回当前结果
- standard：每论断搜索工具调用上限 3–4 次；超限处理 同上
- deep：每论断搜索工具调用上限 3–4 次；超限处理 同上

预算按单论断粒度计，不按整份报告计；查询矩阵的类别数（quick 1 / standard 3 / deep 4）是预算的构成，不是额外预算。

被预算截断的论断须在报告方法论说明中如实标注（如「该论断搜索 4 次后终止，证据未闭合」），不得默默按 CONFIRMED 处理。

Why：预算约束防止单论断吞掉全局核查深度；隐瞒截断则让证据不足伪装成确信。

## T1–TX 信源分层

信源层级决定「能独立锁定哪类论断」，而非可算术累加进置信度的分值：

- T1 — 原始数据发布者（公司财报、政府统计、原始论文）：可独立锁定 L1 数字 / 日期 / 主体事实；优先采用，但需验证源页面真实性
- T2 — 权威专业媒体（Reuters、Bloomberg、Nature、财新）：不能独立锁定，需与 T1 或另一独立 T2 交叉验证
- T3 — 行业分析 / 智库（Gartner、McKinsey、Pew Research）：只作背景参考，不作事实验证依据
- T4 — 评论 / 社论 / 社交媒体：仅作观点参考，不进入 L1 证据链
- TX — 匿名 / 无法溯源：标记「无法核实」，不进入证据链

使用纪律：

- L1 判定除 T1 外，须 ≥2 个独立来源交叉验证
- T2 独家报道在第二个来源出现前，不得升级为 CONFIRMED
- T3 / T4 可引用于报告的框架 / 观点层，不能支撑 L1 判定
- T3 报告须方法论与资助方披露后方可引用

Why 无可信度权重：给每级信源赋百分比权重再算术累加出置信度是伪量化——层级是证据能力的定性边界，不是分值。

## 循环引用检测

三角测量（Triangulation）时检查来源独立性：A 引 B、B 引 C、C 引 A，这个环不算多源。警惕 AI / 内容农场内容互相引用的「衔尾蛇」（Ouroboros）模式。

检测信号：

- 多来源措辞雷同（含相同的错误或相同的模糊表述），是转抄痕迹
- 向上追溯收敛到同一篇原始文章 / 通稿，名为多源实为单源
- 各来源均互引、无一引用一手数据，整组按 TX 处理

环或衔尾蛇确认后，多源按单源计；预算允许时重新搜索独立来源。
