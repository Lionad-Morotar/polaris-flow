# 事实核查核心方法论

由 SKILL.md Workflow B Step 1 调起；Step 3 判定前重读「认知偏差自检」节。定义核查的分诊协议、论断 L1/L2/L3 分层、提取纪律与证伪优先的验证框架。

## 分诊协议

### 范围界定

输入三态，先统一为「待核查文本」再进入提取：

- 论断句：直接进入论断原子化
- URL：先获取全文（工具链见 `fact-check-sources.md`），再从正文提取论断
- 文件路径：先读取整个文件，再从正文提取论断

Why 先取全文：论断脱离上下文即发生语义漂移，只有全文能还原被省略的语境与时间参照。

### 浅材料熔断

输入不足以产出任何可核查论断（纯情绪表达、模糊口号、主谓语缺失）时，输出 0 条论断并停止，不硬凑结论。

Why：核查结论必须证据支撑，无论断可查时诚实停止优于编造——强行产出的核查报告本身就是虚假精确的制造。

### 论断原子化

将文本拆解为最小可验证单元：每个论断只含一个可验证核心（一个数字、一个日期、一个因果关系），且每个论断独立可证伪——一个论断被证伪不得连累其他论断的判定。

复合句必须拆分。如「X 亏损 50 亿美元且即将破产」须拆为两条原子论断——亏损事实（L1，可查财报验证）与破产预测（L2，需竞争框架验证），分别分层、分别判定。

每条论断提取时附四个字段：

- 原文切片：含该论断的原句或原段，保留语境以便溯源
- 本体论层级：L1 / L2 / L3
- 信源链条：作者 → 媒体 → 声称的原始来源，缺失环节标「无法溯源」
- 时间敏感度：高（每日更新）/ 中（季度更新）/ 低（历史事实）

论断数量上限与高影响筛选（高影响 = 涉财务 / 健康 / 安全 / 重大决策，或强情绪修辞）见 SKILL.md 档位路由。

## L1/L2/L3 三层事实模型

核查前先对内容做本体论分层——分层决定策略，不同层级适用不同的验证与判定规则：

- **L1 经验事实**（Empirical Facts）：特征 可量化、可证伪、时间戳明确；核查策略 寻找原始数据源，验证测量方法；输出标记 ✅ 已证实 / ❌ 已证伪
- **L2 解释性框架**（Interpretive Frames）：特征 基于事实的因果解释、意义赋予；核查策略 评估逻辑一致性，寻找竞争性解释；输出标记 🟡 框架A / 🟠 框架B
- **L3 价值判断**（Value Judgments）：特征 应然陈述、风险评估、重要性排序；核查策略 识别价值预设，评估证据支撑度；输出标记 💬 观点 / ⚖️ 多元价值

操作原则：L1 严格验证；L2 呈现多元框架；L3 尊重但标注。L2/L3 不判「错误」——核查在解释层与价值层的任务是呈现多元框架、暴露预设，而非压制观点。

分层争议时就低不就高：L1/L2 难分，先按 L1 验证；L2/L3 难分，先按 L2 呈现。

## SIFT 提取原则

扫描文本时对每个潜在主张应用 SIFT：

- **Stop**：暂停接受，先标记潜在主张，不立即相信或否定
- **Investigate**：追查来源，区分一手 / 二手信息
- **Find**：寻找原始上下文，还原被切除的段落
- **Trace**：追踪引用链条，识别循环引用（检测见 `fact-check-sources.md`）

SIFT 贯穿提取与验证两个阶段，不只是起手式。

## 候选通过纪律

凡能命名证伪路径的论断一律放行进入验证——提取器默默丢弃半信半疑的论断是漏检主因。仅纯 L3 价值判断与重复论断可在提取阶段排除。

## 竞争性假设

对每个 L1 论断生成 ≥3 个竞争性假设（Competing Hypotheses）（支持 / 反对 / 重构），验证各假设的证据分布再作判定——直接搜「是否为真」只会退化为证实性收集。（deep 档对全部 L1 论断执行；quick / standard 档至少对高影响 L1 论断执行。）示例：

- 原文论断：「OpenAI 亏损 50 亿美元，即将破产」
- 假设 A（支持）：烧钱速度确实超过收入，现金流紧张
- 假设 B（反对）：亏损是会计处理，实际运营现金充裕，且持续融资
- 假设 C（重构）：亏损属实，但属战略性投入，非生存危机

- A、B、C 均有证据：⚖️ 争议性事实，并列呈现多方数据
- 仅 A 有强证据：✅ 已证实（注意幸存者偏差）
- B / C 证伪 A：❌ 已证伪

## 查询矩阵

四类查询，证伪优先——证实性查询只用于三角测量（Triangulation）佐证，不作主验证：

- 证实性：「[论断关键词]」+「official report」+「2025/2026」
- 证伪性：「[论断关键词]」+「false」/「misleading」/「controversy」
- 竞争性框架：「[主题]」+「criticism」/「alternative explanation」/「debate」
- 时效性：「[事件]」+「update」/「revised」/「clarification」

每条查询须具体到能返回可证伪证据，泛主题词只会返回背景噪音。

档位差异：quick 档每论断 1 条证伪查询；standard 档执行证实 / 证伪 / 竞争框架 3 类；deep 档执行全部 4 类 + 时间线重建。工具选择与搜索预算见 `fact-check-sources.md`。

## 认知偏差自检

**判定前（Workflow B Step 3）强制重读本节并逐项核对：**

- [ ] **确认偏误**：我是否只搜索了支持原文的关键词？
- [ ] **锚定效应**：是否被原文的第一个数字 / 框架过度影响？
- [ ] **可得性启发**：最新 / 最情绪化的信息是否被过度加权？
- [ ] **权威偏见**：是否因为来源知名而降低验证标准？
- [ ] **归因谬误**：是否将相关性误解为因果性？
- [ ] **二元思维**：是否忽略了「部分属实」的灰度地带？
- [ ] **白大褂效应**：是否因「带引用格式」而高估可信度？（MIT 研究警示）
- [ ] **懒惰假设**：假设读者不会点击链接，关键主张是否已独立验证？
- [ ] **流畅性偏见**：是否混淆了「写得易懂」与「事实」或「置信度」？

任一项命中，先补充对应的证伪或竞争框架查询，再判定。

## 证伪条件压力测试

结论落定前，每个已判定论断强制回答：什么新证据会推翻当前判定？无法命名证伪条件（Falsification Condition）的论断，在报告中降级为「无法核实」并说明。Why：不可被推翻的结论不是核查结论而是信念——能命名证伪条件，是核查对抗性的唯一外在表现。

格式示例：

- 证伪条件：若 OpenAI 发布 Q2 财报显示正现金流 → 修正「即将破产」论断
- 持续跟踪：需监测的关键指标——OpenAI 现金流（季度财报）、软银 OpenAI 持仓变化（监管披露）、企业 AI 采用率（行业报告）
- 复核触发：持续跟踪指标任一变动时，重新验证对应论断

本节的证伪条件与持续跟踪写入报告的「证伪条件与更新协议」节，见 `fact-check-report.md`。
