# 透明背景工作流(transparent 模式)

透明图像通过**色键(Chroma-key)背景生成 + 本地移除**实现:先在纯色背景上生成主体,再用 `remove_chroma_key.py` 把色键颜色转换为 Alpha 通道。

生成阶段的出图后端由 provider 路由决定:色键图的生成走 `resolve_provider.mjs` 解析出的 (provider, model)，bl 与 grsapi 的调用/落盘差异见 `providers.md`。本工作流的色键提示词模板与 `remove_chroma_key.py` 本地移除步骤与 provider 无关，两后端通用。

## 默认序列

1. 生成阶段:提示词要求主体在纯色色键背景上。
2. 选择不太可能出现在主体中的色键颜色:默认 `#00ff00`,绿色主体用 `#ff00ff`,蓝色主体避免使用 `#0000ff`。
3. 生成后运行:

   ```bash
   python3 ~/.claude/skills/flow-image/scripts/remove_chroma_key.py \
     --input <source> \
     --out <final.png> \
     --auto-key border \
     --soft-matte \
     --transparent-threshold 12 \
     --opaque-threshold 220 \
     --despill
   ```

4. 验证输出是否具有 Alpha 通道、边角透明、主体覆盖范围合理,且没有明显的色键边缘残留。如果残留细边,用 `--edge-contract 1` 重试一次;仅在边缘明显呈阶梯状且主体不闪亮/不反光时才使用 `--edge-feather 0.25`。
5. 资源绑定到项目时,将最终的 Alpha PNG/WebP 保存到项目中,不要让项目引用 `~/.flow-image/` 下的文件。

## 色键提示词模板

```text
在纯平纯色 #00ff00 色键背景上创建请求的主体,以便后续移除背景。
背景必须是单一均匀颜色,不得有阴影、渐变、纹理、反射、地面平面或光照变化。
主体与背景之间保持清晰分离,边缘锐利,并留出足够边距。
主体中不得使用 #00ff00。
不要投射阴影、接触阴影、反射、水印和文字,除非明确要求。
```

## 复杂主体判断

以下情况色键移除难以干净处理,应先询问用户是否继续:

- 头发、皮毛、羽毛
- 烟雾、玻璃、液体
- 半透明材质、反光物体
- 柔和阴影、真实产品接地
- 与所有实用色键颜色冲突的主体颜色

确认话术示例:

```text
这个主体的边缘/材质较复杂,色键移除可能残留瑕疵(毛发/玻璃/烟雾类主体典型)。
仍可按色键工作流尝试并验证 Alpha 结果,或改用纯色背景直接交付。是否继续?
```

## 验证清单

- [ ] 输出含 Alpha 通道
- [ ] 四角完全透明
- [ ] 主体边缘无色键色残留(绿边/品红边)
- [ ] 主体覆盖范围合理,无内部镂空误判
- [ ] 抗锯齿边缘自然(软遮罩 + 去溢色生效)
