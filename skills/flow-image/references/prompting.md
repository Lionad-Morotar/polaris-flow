## 结构
- 使用一致的顺序:场景/背景 -> 主体 -> 关键细节 -> 约束 -> 输出意图。
- 包含预期用途(广告、UI 样机、信息图)以设定精致程度。
- 复杂请求使用简短的带标签行,而不是一大段文字。

## 具体性策略
- 如果用户提示词已经具体且详细,将其规范化为干净的规格说明,而不添加创意要求。
- 如果用户提示词比较笼统,仅在能实质性提升输出时添加有品味的细节。
- 将 `sample-prompts.md` 中的示例视为完整撰写的配方,而不是每个请求默认要添加的增强量。
- 照片级真实图像目标时,直接包含 `photorealistic`,并补充具体的真实世界纹理,如毛孔、皱纹、织物磨损、材质颗粒或不完美的日常细节。

## 允许与不允许的增强

对笼统提示词允许的增强:
- 构图和取景线索
- 预期用途或精致程度提示
- 实用布局指导
- 支撑请求的合理场景具体化

不要添加:
- 未暗示的额外角色、道具或物体
- 未暗示的品牌调色板、标语或叙事节奏
- 除非用户或周围布局支持,否则 arbitrary 的左右放置

## 构图与布局
- 仅当确实有帮助时才指定取景和视角(特写、广角、俯视)以及放置位置。
- 高端视觉(海报、广告、封面)优先机制级空间描述,而非构图术语标注:写"上半部三分之二为纯净留白,主体从画面下沿探出仅露上半部,视线被引向主体微距区域",而不是只写"负空间""三分法"。机制描述交代主体与画框的几何关系和视线动线,对模型是强信号;孤立术语是弱信号。
- 如果资源明显需要为 UI 或文案留出负空间,才指出负空间。
- 除非用户或周围布局支持,否则避免做左右布局决策。
- 对于人物,在重要时描述身体取景、比例、目光和物体互动(`全身可见`、`低头看书`、`双手自然握住车把`)。

## 约束与不变量
- 说明什么不能改变(`保持背景不变`)。
- 编辑时使用 `仅修改 X;保持 Y 不变`,并在每次迭代中重复不变量以减少漂移。
- 唯一性约束要显式排他:画面只允许一个某类元素(唯一主星、唯一光源、唯一人物)时,只写位置关系不够——模型会在参照物内外各复制一份;必须追加排他表述("全天只有一颗明亮主星,其余星辰暗淡细小,禁止出现第二颗亮星")。

## 图像中的文字
- 将字面文字放入引号或全大写,并指定字体样式、字号、颜色和位置。
- 如果准确性重要,对不常见的单词逐字母拼写。
- URL、品牌名、账号名等长字符串默认加逐字母锚定(如 Morotar → M-o-r-o-t-a-r):它们在多轮迭代与多比例重抽中最易漂变。
- 图像内文案要求原文呈现,不得多出字符。
- 小文字、密集信息图、数据密集型幻灯片、多字体布局、图例、坐标轴和脚注类需求,在提示词中明确标注高画质要求。

## 输入图像与参考图
- 不要假设用户提供的每张图像都是编辑目标。
- 按索引和角色标注每张图像(`Image 1: edit target`、`Image 2: style reference`)。
- 如果用户提供图像仅用于风格、构图或氛围参考,且未要求修改它们,将其视为带参考的生成。
- 如果用户要求保留已有图像并仅修改特定部分,将其视为编辑。
- 合成时描述图像如何互动(`将 Image 2 的主体放入 Image 1`)。

## 有意识地迭代
- 从干净的基础提示词开始,然后进行小的单次修改。
- 迭代时重新指定关键约束。
- 优先一次有针对性的跟进,而不是重写整个提示词。

## 透明图像
- 透明图像请求的完整工作流见 `transparent.md`。
- 提示词要求纯平纯色色键背景,通常 `#00ff00`;绿色主体用 `#ff00ff`,避免使用主体中出现的颜色作为色键。
- 明确禁止背景中的阴影、渐变、地面平面、反射、纹理和光照变化。
- 要求锐利边缘、充足边距,且主体内部不使用色键颜色。
- 生成后运行 `~/.claude/skills/flow-image/scripts/remove_chroma_key.py` 在本地移除背景,并在交付前验证 Alpha 结果。
- 抗锯齿边缘使用软遮罩和去溢色;硬容差移除主要适用于扁平像素艺术或精确颜色固定物。
- 复杂透明主体(头发、皮毛、玻璃、烟雾、液体、半透明材质、反光物体或柔和阴影)先询问用户是否继续。

## 用例提示
生成:
- photorealistic-natural:像拍摄真实照片一样提示;使用摄影语言(镜头、光照、取景);要求真实纹理;除非要求,否则避免过度风格化精致。
- product-mockup:描述产品/包装和材质;确保干净轮廓和标签清晰;如果需要图像内文字,要求原文呈现并指定字体样式。
- ui-mockup:先描述目标保真度(可交付样机还是低保真线框),然后聚焦布局、层级和实用 UI 元素;避免概念艺术语言。
- infographic-diagram:定义受众和布局流程;明确标注各部分;要求原文文字;密集标签明确标注高画质。
- logo-brand:保持简单和可扩展;要求强轮廓和平衡的负空间;除非要求,否则避免装饰性花哨。
- ads-marketing:像创意简报一样写;包含品牌定位、受众、期望氛围、场景和必须出现的精确标语。
- editorial-poster:构图用机制级负空间描述(上部大面积留白、主体从画框边缘探出仅露局部、微距特写);色彩按主色/过渡/高光/点缀系统描述,整套不超过五种主色关系;排版作为设计维度(字距、不对称漂浮、字体与主体形态呼应);材质写物理属性与光学响应,不写空泛评价。
- productivity-visual:精确命名产物(幻灯片、图表、工作流图),定义画布和层级,提供真实标签/数据,并要求可读字体和精致间距。
- scientific-educational:定义受众、教学目标、必需标签、科学约束、箭头和适合扫描的留白。
- illustration-story:定义画格或场景节奏;保持每个动作具体。
- stylized-concept:指定风格线索、材质表面和渲染方式(3D、绘画感、黏土感),不要 invent 新故事元素。
- historical-scene:说明地点/日期和所需时代准确性;将服装、道具和环境约束在对应时代。

编辑:
- text-localization:只改文字;保留布局、字体、间距和层级;除非必要,否则不添加额外文字或重排。
- identity-preserve:锁定身份(面部、身体、姿态、头发、表情);只修改指定元素;匹配光照和阴影。
- precise-object-edit:精确指定要移除/替换什么;保留周围纹理和光照;其他一切保持不变。
- lighting-weather:只改变环境条件(光、阴影、氛围、降水);保持几何、取景和主体身份。
- background-extraction:简单不透明主体请求干净抠图,放在纯平色键背景上;锐利轮廓;充足边距;无阴影;无边缘光晕;精确保留标签文字;不改变风格。复杂主体先询问。
- style-transfer:指定要保留的风格线索(调色板、纹理、笔触)以及必须改变的内容;添加 `no extra elements` 防止漂移。
- compositing:按索引引用输入;指定什么移动到哪里;匹配光照、透视和比例;保持基础取景不变。
- sketch-to-render:保留布局、比例和透视;选择支持所提供草图的材质和光照,不添加新元素。
