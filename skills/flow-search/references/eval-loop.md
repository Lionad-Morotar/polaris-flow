# 深度研究执行循环手册

由 SKILL.md Workflow C Step 2–4 调起。定义深度研究分支的执行阶段：$mode 判定、查询集群构建、并行搜索分发、master-log 协议、评估器五维 rubric、分级退出标准、循环驱动与最终交付格式。

整体形态是 Evaluator-Optimizer 循环：搜索代理并行撒网 → 评估器以破坏性基调打分找缺口 → 父代理据缺口构建下轮查询 → 直到达标或撞轮次上限。

## 会话目录结构

```
/tmp/flow-search/{YYYY-MM-DD}/{task-name}/
├── brief.yaml              # 研究需求文档（research-brief 阶段产出）
├── master-log.md           # 协调日志：单行时间戳事件
├── report.md               # 最终报告
└── turn-{n}/               # 第 n 轮
    ├── agent-{n}-1.md      # 搜索代理结果（每个代理一个文件）
    ├── agent-{n}-2.md
    └── eval-{n}.md         # 评估器报告
```

子代理结果必须落盘而非返回正文——抓取的多页全文会撑爆父上下文，父代理只消费摘要与评分。

## $mode 判定

按 brief.yaml 的深度信号确定执行档位。**默认 easy**——没有明确深度信号时一律落最低档：搜索是迭代过程，低档不满足可应用户要求加深，高档开销（并行代理 + 评估轮次）不可退。

- 默认（无明确深度信号），或「快速概览」：$mode easy；并行代理数 2
- 「标准研究」，或研究模式为 comprehensive：$mode medium；并行代理数 3
- 「穷尽研究」+ 质量阈值高：$mode hard；并行代理数 4

## 初始方向策略（第一轮查询集群）

- focused：优先支持/反对假设的证据；盯权威来源（官方文档、论文、基准测试）；主动找矛盾观点与反证
- scan：先撒大网取概览；识别关键概念与术语；定位该领域的权威来源
- comprehensive：多角度并行（正面/负面/学术/实践）+ 时间维度（历史演变+最新进展）+ 地域维度（国际主流+中文社区）

查询集群构建技巧：并排比较词（vs / comparison / benchmark）、时间限定（当年与前一年年份）、具名评估数据集/框架、特定站点（GitHub issues、HN、StackOverflow）、学术检索（paper / arxiv）、多语种搜索。

brief.yaml 的「特殊角度」强制对应查询，不可省略：

- negative：`{topic} limitations problems issues`
- chinese：`{topic} 中文 踩坑 实践`
- academic：`{topic} paper arxiv research`
- github-issues：`{topic} github issues bug`

## 并行搜索分发

**一条消息内发出多个 Agent 调用**（同一轮的所有搜索代理并行启动），`subagent_type: general-purpose`，每个代理分配不同查询集群。

搜索代理 prompt 模板：

```
搜索："{query}"（可含变体查询）
目标：{研究目标}

**输出文件：** /tmp/flow-search/{YYYY-MM-DD}/{task-name}/turn-{round}/agent-{n}.md

**工具线（按优先级，禁用内置 WebSearch / WebFetch）：**
deepseek-search / open-websearch / glm-*（搜索）→ glm-web-reader / open-websearch fetch（抓取全文）→ flow-web（兜底，前三者出错时启用）

**⚠️ 429 规则：** 遇到 Rate Limit 立即停止，返回已获取的部分结果 + 错误说明，不无限重试、不切换工具硬刷。

对每个相关结果：抓页面内容，提取与研究目标相关的关键发现，记录 URL、标题、要点、相关度（1–5）。结果不足时尝试变体查询。关注事实与有数据支持的论断。

写入文件格式见下。**返回给父代理：仅文件路径 + 一行状态摘要**（如「完成，12 条结果」），不要返回正文。
```

agent-{n}.md 格式：

```markdown
# Search Agent {round}-{n}

## 元数据
- 查询："{query}"
- 集群：{cluster_name}
- 状态：{completed/partial/error}

## 搜索结果

### 结果 1：{title}
- URL: {url}（相关度 {1-5}/5）
- 关键发现：
  - {要点}
- 引用："{相关摘录}"

## 摘要
- 结果数量：{N}，平均相关度：{X}/5，遇到错误：{none/429/other}
```

## master-log.md 协议

父代理只记协调事件（单行时间戳），不记搜索详情：

```
[14:30:00] [INIT] 目标：{goal}，mode={mode}，轮次上限={max}
[14:30:05] [AGENT_START] agent-1-1，查询：{query}，集群：comparison
[14:30:50] [AGENT_DONE] agent-1-1，结果：12，耗时：45s
[14:31:00] [EVAL_START] 第 1 轮评估
[14:33:30] [EVAL_DONE] 均分：3.2/5，决策：CONTINUE
[14:33:40] [ROUND_END] 第 2 轮，集群：{缺口驱动的新集群名}
[14:45:00] [COMPLETE] 总轮次：3，最终均分：4.6/5
```

## 评估器（破坏性基调）

每轮搜索完成后起一个评估器子代理（`subagent_type: general-purpose`）。基调是**挑战性和破坏性**——它的职责是找缺口，不是表扬。

评估器 prompt 模板：

```
你是研究质量评估器，基调：挑战性和破坏性。

研究目标：{goal}
质量阈值：{high/medium/low}（来自 brief.yaml）
研究模式：{focused/scan/comprehensive}
时效要求：{latest-only/history-ok/none}

**读取：** /tmp/flow-search/{date}/{task}/turn-{round}/agent-*.md
**输出：** /tmp/flow-search/{date}/{task}/turn-{round}/eval-{round}.md

五维评估（每项 1–5 分，评分校准见本手册校准表）：
1. 覆盖度 — 是否从多个角度回答了核心问题？
2. 来源质量 — 来源是否权威可信？
3. 一致性 — 来源在关键事实上是否一致？
4. 具体性 — 论断是否有数据/案例支持？
5. 时效性 — 信息是否最新且相关？

时效调整（以会话当前日期为基准）：时效要求 latest-only 时，两年前的信息降 2 分；history-ok 不扣分但需标注时间。

输出格式见下。缺口分析与改进建议必须具体到可执行的查询，模糊的「再搜一下」不合格。
**返回给父代理：仅文件路径 + 均分 + 决策。**
```

eval-{n}.md 格式：

```markdown
# Evaluator - Turn {round}

## 质量评估

| 维度 | 评分 | 依据 |
|---|---|---|
| 覆盖度 | {1-5} | {简要说明} |
| 来源质量 | {1-5} | {简要说明} |
| 一致性 | {1-5} | {简要说明} |
| 具体性 | {1-5} | {简要说明} |
| 时效性 | {1-5} | {简要说明} |

**均分**：{average}/5

## 缺口分析
1. {具体缺口}
2. {具体缺口}

## 改进建议（可直接作为下轮查询）
1. {具体查询 + 目标站点 + 解决的缺口}
2. {具体查询}

## 决策：{CONTINUE / COMPLETE}
```

### 评分校准表

- 5：所有关键角度深度覆盖；多个权威来源；强烈共识；贯穿具体数据；最新且注明日期
- 4：大部分角度覆盖；以权威为主；微小差异；大部分具体；大部分最新
- 3：有缺口但可接受；好坏混合；部分矛盾；具体与概括混合；部分较旧
- 2：重大缺口；低质量为主；重大矛盾；主要是概括；明显过时
- 1：缺少关键视角；未经验证来源；完全矛盾；模糊论断；严重过时

## 退出判定（按 $mode 分级）

- easy：均分 ≥4 且无维度 ≤2；轮次上限 2
- medium：均分 ≥4.5 且无维度 ≤3；轮次上限 3
- hard：全维度 ≥4 且均分 ≥4.5；轮次上限 4

纪律：

- **均分不可掩盖单维短板**——地板条件（无维度 ≤X）与均分条件必须同时满足，不允许「总体不错」的综合判断绕过。
- 撞轮次上限即退出，未达标的维度必须在 report.md 局限性一节如实说明。
- 用户随时可强制停止。

## 循环驱动（父代理 inline）

评估器决策 CONTINUE 时，父代理**直接读取 eval-{n}.md 的改进建议构建下一轮查询集群**——不设独立 optimizer 子代理，评估器已产出可执行查询，中间再加一层只会丢语境。

- 针对低于地板的维度优先补查询，禁重复先前查询。
- 分数停滞（连续两轮无提升）→ 换方法而非加量：换语言、换引擎、换来源类型（从博客转论文/issues，或反之）。
- 轮次节奏：第 1 轮广撒 → 第 2 轮补缺口 + 搜矛盾证据 → 第 3 轮起攻坚固缺口与原始来源。

## report.md 交付格式

```markdown
# 研究报告：{task-name}

## 执行摘要
{回答核心问题的 2–3 段文字}

## 关键发现（含置信度）

| 发现 | 证据 | 置信度 |
|---|---|---|
| {要点} | {来源} | 高/中/低 |

## 质量评估
- 覆盖度 {score}/5 — {一句话说明}
- 来源质量 {score}/5 — …
- 一致性 {score}/5 — …
- 具体性 {score}/5 — …
- 时效性 {score}/5 — …

## 局限性
{仍不确定的内容；撞轮次上限退出时，列出未达标维度及原因}

## 来源
{带 URL 的关键引用，每条追加 (置信度: X)}
```

报告完成后向用户呈现执行摘要 + 关键发现表，并指出完整会话位置（`/tmp/flow-search/{date}/{task}/master-log.md`），询问是否深入特定发现。如用户有文档存档技能（如 distill 归档到笔记系统），按用户指示执行。

## 示例会话（focused / high / medium 档）

主题：「LLM 代理在 PowerShell 上表现比 Bash 差的证据」。brief：focused / high / latest-only / detailed-report / [github-issues]；用户明确要求「标准研究」→ $mode = medium（3 代理，上限 3 轮）。

- **第 1 轮**（3 代理：通用比较 + 基准搜索 + GitHub issue 分析）→ 评估：覆盖度 3「需要更具体的基准」、具体性 2「需要实际数字」→ CONTINUE
- **第 2 轮**（补 SWE-bench 结果、pass@k 指标）→ 评估：覆盖度 4、具体性 4、一致性 3「矛盾论断未解决」→ CONTINUE
- **第 3 轮**（针对矛盾论断搜原始来源）→ 全维度 ≥4 且均分 ≥4.5 → COMPLETE
- 交付：带置信度与五维质量评估的验证摘要。

## 注意事项

1. **评估器不可跳过**：没有质量评估的搜索不知道何时该停
2. **反馈要具体**：改进建议必须是可以直接发出去的查询，不是方向性口号
3. **停滞即换法**：分数不涨时换语言/引擎/来源类型，同质查询加量无效
4. **工具线纪律**：禁用内置 WebSearch/WebFetch；全线不可用则停止并报告，不凭先验知识编造发现
5. **前期澄清决定后期质量**：brief.yaml 缺字段会直接削弱评估器的判定依据
