# 文档溯源执行手册

由 SKILL.md Workflow A Step 1–3 调起。定义文档溯源分支的目标分类、三层查找策略与工具链、输出格式与置信度规则。

## 查询目标分类

从用户消息或对话上下文中提取需要溯源的对象，并分类：

- **配置项 / CLI 参数**（带有 `--flag`、`json` 字段、环境变量形式）：官方文档 CLI/API Reference
- **依赖库 / 工具用法**（涉及第三方包、框架、CLI 工具）：官方 README / 文档站
- **项目约定**（分支策略、目录结构、代码风格等团队决策）：项目内文档
- **语言 / 平台特性**（语法、类型系统、运行时行为）：官方文档 / Release Notes / Spec

## 三层查找：从内到外，找到即停

### 第一层：项目内约定

项目自身是最权威的"为什么要这样做"的来源。

1. `CLAUDE.md` / `AGENTS.md` — 项目级 AI 协作约定
2. `docs/` 目录下的相关文档
3. `CONTRIBUTING.md`、`DECISIONS.md` 等开发规范
4. 代码注释、commit message 中的引用

### 第二层：官方文档

工具/库的权威文档是配置项和用法的最佳来源。按优先级使用工具链：

- 1：Context7 — MCP：`resolve-library-id` + `query-docs`；适用主流库/框架/CLI 的结构化文档检索
- 2：zread — MCP：`search_doc` / `read_file`；适用 GitHub 项目的仓内文档、issues、commits
- 3：glm-web-reader — MCP：`webReader`；适用已知 URL 的官方文档站页面抓取
- 4：open-websearch — MCP：`search` + `fetchWebContent`；适用定位官方文档站的具体页面 URL

**禁用**内置 WebSearch / WebFetch（用户全局偏好，且命中率与绕墙能力都差）。

### 第三层：社区实践

当官方文档不覆盖时，从社区补充佐证。

1. Stack Overflow / GitHub Issues / Discussions（经 zread 或 open-websearch）
2. 知名项目的同类配置示例
3. 行业最佳实践文章

## 输出格式

找到来源后，按以下格式输出：

```markdown
## 改动/主题: [简要描述]

### 1. [来源类型] [来源名称]

**来源**: [文档链接或文件路径] (置信度: [高/中/低])
**配置小节**: [具体的章节/选项]
**核心说明**:
> [引用原文]

**相关配置**:
| 选项 | 说明 |
|------|------|
| ... | ... |

### 2. [项目约定]

**来源**: [文件路径] (置信度: 高)
**说明**: [项目特定的约定说明]

### 总结

| 配置项 | 文档源头 | 链接/路径 | 置信度 |
|--------|----------|-----------|--------|
| ... | ... | ... | ... |
```

## 置信度规则

对每一个来源，评估其权威性和可靠性，并在括号内标注置信度：

- **高**：官方文档、项目内约定文件、Release Notes、源码中的明确注释
- **中**：知名社区文章、Stack Overflow 高赞回答、GitHub Issues/Discussions 中的官方人员回复
- **低**：个人博客、未经广泛验证的第三方内容、机器翻译或信息间接转述

**特别说明**：当来源为网页链接或媒体资源时，**必须**在链接后追加 `(置信度: X)`。

## 注意事项

1. **区分层级**：明确区分官方文档、项目约定、社区实践
2. **提供上下文**：不仅给出链接，还要说明为什么这个来源权威
3. **完整性**：如果涉及多个配置项，为每个都找到来源
4. **可追溯性**：优先使用 Context7 等结构化文档，其次是官方文档链接，最后是社区来源
