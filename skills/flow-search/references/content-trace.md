# 内容溯源执行手册

由 SKILL.md Workflow B Step 1–6 调起。定义内容溯源分支的二手判别、指纹提取、语言还原、搜索与抓取工具链、核验纪律与输出格式。

转载内容（公众号、B站、抖音、知乎转述、视频号、媒体二手报道）通常删掉了原始链接，但它携带的"硬信息"是不可压缩的指纹。本手册用指纹反查 + 绕墙抓取 + 传播链回溯，定位到 canonical（权威原始）出处。

## 适用判别（先判断要不要溯源）

先快速判断输入是否为二手转载，避免对一手内容做无用功。

二手信号（命中任一即需要溯源）：

- 无原始链接，或"阅读原文"指向同平台内另一篇
- 标题煽情 / 价值嫁接（例：「AI 挽救了 35 岁现象」）
- 数据来源模糊（"海外有人做了…"、"据说"、"有研究发现"）
- 平台是搬运平台（公众号、B站、抖音、知乎转述、视频号、内容聚合站）
- 文字明显是转述口吻（"某某最近发了一条思考"、"本期内容源自…"）

一手信号（无需溯源，直接用，对应 SKILL.md Step 1 早退）：

- 官方文档站、官方工程博客原文、论文 preprint、官方 X/LinkedIn 一手帖
- 已带 canonical 链接且内容与原文一致

## 1. 提取不可压缩指纹（fingerprint）

从转载内容里提取三类"硬信息"——它们唯一性强、跨语言稳定、搜索引擎能精确命中。

- 硬数字（5306 / 1680 / 12.2 年 / 686）：唯一性最强，几个数字组合即可定位唯一文档
- 专名（人名（Boris Cherny）、产品名（River / Aquifer）、术语（RLHF））：跨语言稳定，不随翻译变形
- 独特短语（"no DM"、"melt into a role"、"under the river"）：原文的独特表达，转载者一般照搬

优先级：硬数字 > 专名 > 独特短语。能凑齐两类基本稳了。

## 2. 语言还原（中 → 英 / 英 → 中）

中文转载里的专名往往是意译，直接拿中文标题去搜命中率很低。先把专名反推回原文目标语言的表达：

- "不准私聊"："no DM" / "public channel"
- "职能融化 / 角色浮现"："melt into a role"
- "内部 Agent"："internal agent"
- "五个阶段"："five stages"
- "工程军团"："infrastructure army"

用目标语言的指纹组合去搜，命中率远大于标题直译。

## 3. 搜索（指纹组合，禁标题直搜）

- 1：`deepseek-search` — CLI，带 `--json` 供程序消费
- 2：`open-websearch` — MCP：`mcp__open-websearch__search` + `mcp__open-websearch__fetchWebContent`
- 3：`glm-*` — MCP
- fallback：`flow-web` — 浏览器自动化技能，前三者出错时启用

**禁用**内置 WebSearch / WebFetch（用户全局偏好，且命中率与绕墙能力都差）。

纪律：

- query 用语言还原后的目标语言指纹组合，不要用中文标题
- 多引擎并行（duckduckgo + bing + brave），单一引擎常漏
- 工具链全部不可用：停止并报告，绝不凭先验知识编造出处

## 4. 绕墙抓取全文（fallback 序）

定位到候选原文后，抓全文核验。不同站点阻力不同，按以下顺序 fallback：

1. **reader 类 SSR 抓取**（主力）：`glm-web-reader` / `web-reader`
   - X / LinkedIn Pulse / shopify.engineering 这类站点的 SSR（服务端渲染）里常含完整正文，免登录即可拿到全文
2. **open-websearch fetch**：注意它会误判部分公网域名为"内网"而拦截（如 shopify.engineering），拦截就换 reader
3. **flow-web**（兜底）：控制真实浏览器，走用户登录会话；X 登录墙、公众号正文全文、需 JS 渲染的页面靠它

## 5. 逐条核验（防同名蹭文）

抓到候选原文后，用"四件套"逐条比对，确认是同一篇：

- 原文链接（canonical URL）
- 作者（署名 / handle）
- 发布时间
- 关键数据 / 关键论点（逐条核对，不是"看着像"）

警惕两类陷阱：

- **同名不同源**：有人蹭热门标题发软文。例：《The Five Stages of AI-Native Engineering》原标题被 EncodeDots 借用发招聘软文，结尾署名 "At EncodeDots"——看结尾署名、看有无实质指纹内容即可识破。
- **标题撞车**：不同文章用了相似标题。靠硬数字和独特短语区分，不靠标题。

## 6. 识别二次创作层（增值，但重要）

中文转载常做"价值嫁接"——把原文事实包装成原文没有的叙事角度。溯源结果里要区分：

- **原文事实**：原作者实际写的、可核验的内容
- **中文解读 / 价值投射**：转载者添加的角度、情绪、本地化类比

典型嫁接案例：「AI 挽救了 35 岁现象」——原文（Sebastian Cuadros 的 LinkedIn 分析）只陈述"Anthropic 中位工程师经验 12.2 年、应届生基本不招"，"35 岁现象"是中文号对照中国职场焦虑嫁接的价值投射，原文无此角度。输出时分别标注，不混为一谈。

## 7. 输出传播链

把溯源结果按传播链呈现，让使用者看清"当前看到的内容"和"原始出处"之间隔了几手：

```
原始出处（canonical） → 英文转载 / 二次解读 → 中文搬运 → 当前 URL
```

每一环标注：增损了什么（删了数据？加了角度？）+ 置信度。

## 输出格式

找到原始出处后，按以下结构输出：

```markdown
## 原始出处: [原标题]

**原文链接**: [URL] (置信度: 高/中/低)
**作者**: [姓名 / handle]
**发布时间**: [日期]
**平台**: [官方工程博客 / X / LinkedIn Pulse / 论文 preprint 等]

### 核验（四件套逐条比对）
| 指纹 | 转载内容 | 原文 | 吻合 |
|------|----------|------|------|
| 硬数字 | ... | ... | ✅ |
| 专名 | ... | ... | ✅ |

### 传播链
[canonical] → [中间转载] → [当前 URL]
每环增损说明。

### 二次创作层（如有）
- 原文事实：...
- 中文解读 / 价值投射：...（转载者添加，原文无）

### 延伸（可选）
原文中比中文版多 / 少的、值得读的硬货。
```

canonical 定位不到时：输出可追溯到的最远一环 + 低置信标注，不硬凑"找到了"。

## 置信度规则

- **高**：官方一手原文（官方博客、作者本人 X/LinkedIn 原帖、论文 preprint）
- **中**：官方二次（同一官方站点的转载）、权威媒体一手报道
- **低**：第三方搬运、无法定位 canonical 时的最佳猜测

网页 / 媒体链接后**必须**追加 `(置信度: X)`。

## 实战锚点（方法论的真实出处）

这些案例是本手册方法论的来源，可作参照：

- **Shopify River**：专名反推英文（"不准私聊" → no DM）+ reader 抓 SSR 全文 → `shopify.engineering/under-the-river`
- **Limestone 五阶段**：专名 + 派驻数字指纹 + X 登录墙走 reader → `x.com/mardehaym/article/...`
- **Boris Cherny 五原型**：专名（Boris Cherny）+ 独特短语（melt into a role）+ X SSR 含全文 → `x.com/bcherny/status/...`
- **Anthropic 1680 简历**：硬数字指纹（5306 / 1680 / 12.2）+ 识别中文标题嫁接（"35 岁现象"原文无）→ LinkedIn Pulse - Sebastian Cuadros

## 注意事项

1. **指纹优先于标题**：永远用硬数字 / 专名 / 独特短语搜，不用转载标题直搜
2. **核验不可省**：定位到候选不算完成，四件套逐条比对才能确认
3. **区分事实与解读**：把原文事实和转载者的价值投射分开标注
4. **工具 fallback**：reader 抓不到 → open-websearch → flow-web，禁用内置 Fetch/WebSearch
5. **canonical 优先**：多个转载并存时，定位到最原始的那一篇（通常发布最早、作者本人发布）
